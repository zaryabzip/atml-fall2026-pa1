MMD estimator change -- recorded 2026-09-23, BEFORE any Task 3 Sketch evaluation (task3/results/final_eval did not exist).

What changed: shared/mmd.py now uses the UNBIASED MMD^2 estimator by default (diagonal self-similarity terms dropped).
Task 2 DAN and Task 3 DAN-DG both use it (mmd_unbiased: true in dan.yaml and dan_dg.yaml), so they still share one MMD.
Nothing else changed: lambda_DG = 1 and lambda_MMD = 1 for the main runs, same kernels, same study values {0.1, 1, 10}.

Why (source-side evidence only):
  - With the biased estimator, DAN-DG at lambda_DG = 1 (and 10) collapsed from epoch 1: train cls_loss ~1.94 = ln 7,
    mean SOURCE-val macro-F1 0.051 (one class predicted). On source images, 96.7% of feature values were zero and the
    median pairwise squared feature distance was ~1e-5.
  - DAN-DG compares 8 vs 8 images per domain pair. The biased estimator's same-distribution floor, ~2(3 - k)/n, is then
    ~3x larger than for Task 2 DAN (24 vs 24), and minimizing it rewards collapsing every feature to one point.
  - A 3-epoch diagnostic with the unbiased estimator (task3/results/diag_dan_dg_unbiased) trained normally (source-val F1 0.90).

What was NOT used: no Task 3 Sketch result (none existed). Task 2 Sketch results were not used for this choice.
Task 2 DAN runs were retrained with the new estimator; Task 2 is allowed to see Sketch.

Old biased-estimator runs are kept, not deleted:
